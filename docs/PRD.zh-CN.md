# 产品需求

[English](PRD.md) · [简体中文](PRD.zh-CN.md)

## 产品范围

首个可用版本是一个 Android APK，包含 Flutter 设置界面、Kotlin Android 能力层、运行在 APK 进程内并经过认证的 Streamable HTTP MCP 服务，以及由同一进程提供的调试页面。

产品名称为 **ARMCP（Android Root MCP）**。Android 应用 ID 保持为 `com.doublecat.android_root_mcp`。

## 用户故事

1. 作为操作人员，我可以看到 Root 未知、不可用、可用或检查失败，并在 Root 不可用时点击明确的授权尝试按钮。
2. 作为操作人员，我可以全局开启或关闭 MCP，并看到有效地址、端口、权限状态和服务状态。
3. 作为操作人员，我可以创建一次性、可重复使用、固定时长或不限时令牌，为每个令牌独立选择工具，并删除令牌。
4. 作为 MCP 客户端，我可以使用 Bearer 令牌认证 `/mcp`，并且只能调用该令牌允许且设备支持的工具。
5. 作为开发者，我可以打开 `/debug/`，输入令牌，发现并执行工具，查看结构化输出以及包含 HTTP 状态和耗时的调用记录。
6. 作为开发者，我可以在 `/debug/` 中检查 `view_tree` 或 `view_content`，从树或屏幕边界框选择元素，查看路径、XPath（适用时）、属性、边界、大小和中心点击坐标，并执行中心点击。
7. 作为 MCP 客户端，我可以读取已安装应用、应用权限、定位状态、电池、网络、显示信息和当前 UI 层级/内容，无需截图。
8. 作为操作人员，我可以看到 Root、Android API、网络和工具能力错误，而不会被静默切换到其他能力。
9. 作为操作人员，我可以确认风险提示，并要求 ARMCP 使用 Root 尝试授予 APK 声明的全部权限，同时查看每项结果。
10. 作为操作人员，我可以将 ARMCP 留在后台；启用的 MCP 服务通过可见的 Android 前台服务通知继续运行。
11. 作为操作人员，我可以启用自动权限尝试。确认风险提示后，ARMCP 会在 MCP 启用时以及应用在 MCP 已启用状态下打开时重试。
12. 作为 MCP 客户端，我可以提供 XPath，让 ARMCP 在目标元素的屏幕边界内选择一个硬件随机点并点击。
13. 作为操作人员，我可以选择 Root 或非 Root 运行方式，并通过一个操作打开所需的无障碍设置。
14. 作为操作人员，我可以在两种运行方式下开启 TalkBack 适配；Root 模式允许临时自动恢复，非 Root 模式引导我进入 Android 设置。
15. 作为操作人员，我可以开启 Root TalkBack 恢复偏好；TalkBack 不会立即启动，只会在 UI 读取失败且截图确认屏幕有内容时临时启动，并在读取后恢复原状态。
16. 作为操作人员，我可以使用四个底部区域：主页、运行方式与权限、令牌管理、设置。
17. 作为操作人员，我可以选择跟随系统语言；不支持的系统语言回退到英文，也可以显式选择 English 或中文。

## 验收标准

- 首次安装和明确停止后，全局开关均为关闭。
- `/mcp` 拒绝缺失、格式错误、过期和已消费令牌；已删除令牌不再认证成功。
- 令牌密钥只在创建时显示，存储时只保存验证值。
- MCP 进程默认以只读方式运行；新令牌只启用只读工具，`shell_exec` 默认关闭。
- 每个令牌拥有独立工具允许列表；`tools/list` 和 `tools/call` 都执行该限制。
- 调试页面使用同一个经过认证的 `/mcp` 端点，默认不持久化令牌。
- 每个工具声明所需能力，并在能力不可用时返回稳定错误码。
- Root 通过运行时检查确定；安装 APK不能视为设备已有 Root。
- Root 不可用时，主页显示 Root 授权尝试入口；Root 可用后隐藏该入口。
- 主页显示 Android 能力、Root、非无障碍应用权限、无障碍服务和 MCP 开关状态。
- 设置保存 Root/非 Root 运行方式；运行方式与权限页面随保存的模式变化。
- 底部导航提供主页、运行方式与权限、令牌管理和设置。
- 默认语言跟随系统；不支持的系统语言使用英文；显式选择 English 或中文后覆盖系统设置。
- 全部权限操作必须由用户触发、经过风险确认、仅限 Root，并且只处理 APK 声明的权限，同时报告 Android 拒绝的权限。
- 自动权限尝试默认关闭；用户启用时显示风险提示，之后按保存的选择执行。
- 调试控制台适配视口并支持滚动；UI 检查器保持树和边界模型布局一致。
- 选中的边界框显示为红色；嵌套元素可以独立选中并优先于父元素处理点击。
- 启动器前景图位于 Android 安全区域内，避免图标边缘裁切。
- `random_tap_by_xpath` 只处理一个有有效边界的 XPath 元素，优先使用 `/dev/hwrng`，不可用时使用 Android `SecureRandom`，在完整边界矩形内均匀取样，并报告随机来源。
- 启用后的监听器由前台服务管理，应用退后台时仍可运行；关闭 MCP 后停止服务。
- UI 检查必须披露 Android UiAutomation 方式和权限；当前主要实现使用 ARMCP 无障碍服务。
- 非 Root UI 检查和支持的手势/文本操作使用显式启用的 ARMCP 无障碍服务；Root 不被描述为通用的私有视图树绕过方式。
- Root TalkBack 适配在满足 UI 读取恢复条件前只保存偏好；非 Root 适配只打开系统设置引导。
- 运维文档明确说明绑定地址、端口、明文/TLS 策略、权限和生命周期。

## MVP 工具分组

| 分组 | 原子工具 |
| --- | --- |
| 设备 | `device_status`、`root_status`、`screenshot`、`battery_status`、`network_status`、`display_info` |
| 应用 | `launch_app`、`list_apps`、`app_permissions` |
| 定位 | `location_status`、`get_location` |
| 输入 | `tap`、`swipe`、`input_text`、`key_event`、`gesture` |
| UI 读取 | `view_tree`、`view_content` |
| Shell | `shell_exec` |

以上是原型工具契约。Root、运行时权限、API 版本、传输和目标设备验证仍是发布门槛。UI 检查会说明其 Root UiAutomation 后端，不被描述为隐形的通用应用控制。`view_tree` 返回可读 XML，`view_content` 返回可读 JSON；二者都包含屏幕边界和中心点击坐标。

## 当前实现状态

当前原型实现了设备状态、运行时 `su -c id` 检查、用户触发的 Root 授权尝试、需风险确认的 Root 权限操作、持久化 MCP 总开关、由可见前台服务管理的认证本地网络 MCP 服务、四种令牌模式、独立工具开关、物理删除令牌、同源调试表单、设备/输入工具和格式化 Root UI 检查。完整 OAuth 授权流程和目标设备验证仍需在发布前完成。
