# 运行手册

[English](Operation.md) · [简体中文](Operation.zh-CN.md)

## 启动和停止

操作人员在 Flutter 界面启用 MCP。应用检查 Root 能力、本地网络权限、端口有效性和令牌策略，然后启动 ARMCP 前台服务。监听器启用时，服务显示持续通知，即使 Flutter 页面退后台也会显示。关闭开关会关闭监听器、停止服务并中断新的请求执行，不会静默重启。Android 强制停止、设备关机、策略限制或进程/服务终止仍可能停止服务；下次明确启用或符合条件的服务重启会报告状态。

服务器使用有界客户端执行器，最多同时处理四个请求，并排队最多 32 个连接；超出部分关闭。请求体上限为 1 MiB。停止 MCP 会关闭监听器并中断客户端执行器，反复切换开关不会不断累积线程。

## 令牌

- 只能从 Flutter 操作界面或经过认证的本地控制路径创建令牌。
- 密钥只显示一次，请在离开令牌页面前保存。
- 删除疑似泄露或不再使用的令牌；删除会立即移除验证值和元数据。
- 不限时模式需要明确选择，并且可随时删除；它不是默认值。
- 新令牌默认启用只读工具。启动、输入和 Shell 操作分别保持关闭；`shell_exec` 始终作为高风险工具单独选择。
- 进程重启后，可重复、固定时长和不限时令牌及其工具选择会保留。一次性令牌只有在尚未被原子消费时才能继续使用；此行为需要持久化测试验证。

## 调试页面

MCP 启用时，服务在本地网络接口的 `8787` 端口监听。打开显示的 `/debug/` 地址，输入当前可重复使用的令牌，再选择刷新工具或执行工具。调试页面由 APK 的 MCP 服务提供，并向同源 `/mcp` 发送经过认证的 POST 请求。设备和电脑可通过 LAN 互相访问时，无需 `adb reverse`。

对于 CC Switch 等 HTTP MCP 客户端，认证头必须包含认证方案。端点兼容使用 `ping` 探测的旧版客户端，也支持 `server/discover`、`initialize`、`tools/list` 和 `tools/call`：

```json
{
  "type": "http",
  "url": "http://<device-lan-ip>:8787/mcp",
  "headers": {
    "Authorization": "Bearer <reusable-token>"
  }
}
```

令牌本身不是完整的 `Authorization` 头。直接使用 `armcp_...` 会返回 `401`；必须使用 `Bearer armcp_...`。MCP 客户端会分别发送初始化、工具发现和工具调用请求，因此应使用可重复或固定时长令牌。一次性令牌会在第一个成功请求后消费。

Flutter 界面显示当前调试地址、MCP 地址和监听状态。调试页面只需输入一次令牌即可执行 MCP 操作。调试页面在所选本地接口上公开访问；MCP 请求仍受 Bearer 令牌保护。

## 语言

控制界面支持 System、English 和简体中文。默认选择 System：设备使用简体中文时显示中文，其他系统语言使用英文。也可在设置中显式选择 English 或简体中文，选择后立即应用于 Flutter 界面；MCP 协议和调试端点行为不变。

调试页面使用同一持久化语言偏好。页面中的语言选择通过 `POST /debug/locale` 写入设置并重新加载，因此 APK 下次显示时使用相同语言。

## 主导航

应用包含四个底部页面：

- **主页：**Android 能力状态、Root 状态及授权入口、非无障碍应用权限、无障碍服务和 MCP 开关。
- **运行方式与权限：**Root 模式显示 Root 权限操作；非 Root 模式显示 ARMCP 运行支持和无障碍设置引导。
- **令牌管理：**创建令牌、选择工具允许列表和删除令牌。
- **设置：**Root/非 Root 运行模式和界面语言。

设置保存在 `android_root_mcp_settings.xml`，并遵循 Android 备份/设备迁移规则。普通 APK 升级需保持相同应用 ID 和签名身份才能保留本地数据。卸载后重装、清除应用数据、更改应用 ID 或使用不同签名安装会删除或隔离原有设置。备份恢复还取决于 Android 备份服务和设备设置。ARMCP 是产品名称，不会替换应用 ID。

## 诊断

显示 Root 状态、Android API、目标 SDK、绑定模式、权限、开关状态和最近错误码。持久化日志不得包含令牌原文、不受限的 Shell 输出或完整截图。

## 全部权限

ARMCP 提供默认关闭的“自动尝试授予全部权限”开关。启用前会显示风险提示，因为 Root 会尝试授予 APK 声明的全部权限；若 ARMCP 进程被入侵，影响范围可能扩大，也可能绕过正常的用户授权流程。确认后，Android 保存此选择，并在 MCP 启用以及应用打开且 MCP 已启用时执行有界授权尝试。结果显示总状态，只逐项列出失败权限；已授予权限汇总显示。签名、特权、特殊访问、通知、设备策略和系统限制权限不保证可以授予，拒绝结果会显示。关闭开关会停止未来的自动尝试，不会撤销已授予权限。

UI 检查使用声明了 `canRetrieveWindowContent=true` 的 ARMCP `AccessibilityService`。该服务是主要后端，可读取活动窗口的 `AccessibilityNodeInfo` 树，而不会注册另一个 UiAutomation 会话。动态应用可能在读取期间使节点失效，因此节点刷新和子项读取采用尽力尝试、有限重试及最近完整快照回退。服务已连接时，不会仅因窗口暂时不可读就切换到 `uiautomator dump`，而会返回无障碍服务检查错误。Root 可用时，ARMCP 会尝试启用这项特殊访问；Root 不可用时，界面打开 Android 无障碍设置供用户确认。只有无障碍服务不可用时才使用 Root `uiautomator dump` 回退；若其他自动化会话占用 UiAutomation，可能返回 `UI_AUTOMATION_CONFLICT`。

## TalkBack 操作策略

- **非 Root 模式：**TalkBack 控件用于打开 Android 无障碍设置，由用户自行启用。ARMCP 不修改安全设置。
- **Root 模式：**控件表示允许按需恢复。打开页面或勾选控件时都不会启动 TalkBack，也没有单独的持久启动操作。
- Root 模式下，`view_tree`/`view_content` 检查失败且有界截图确认屏幕存在内容时，ARMCP 临时启用 TalkBack，重试一次，然后恢复原有无障碍服务列表和全局无障碍开关。
- 偏好关闭、Root 不可用或设备未安装 TalkBack 时，不执行回退并返回原始结构化 UI 错误。

## 事故处理

1. 关闭 MCP 总开关。
2. 删除所有有效令牌。
3. 收集已脱敏的审计元数据及设备/API 信息。
4. 重新检查 Root 和网络状态后再启用。
5. 将失败请求整理成不含密钥的最小复现用例。
