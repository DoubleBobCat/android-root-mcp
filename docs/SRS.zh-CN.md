# 软件需求规格

[English](SRS.md) · [简体中文](SRS.zh-CN.md)

## 功能需求

### FR-01 全局生命周期

应用必须持久化一个全局 MCP 开关。启动服务需要开关已开启、配置有效、认证策略可用以及所需本地网络权限。启用期间监听器必须由可见的 Android 前台服务管理，使 Flutter 页面退后台不会停止服务。停止服务必须关闭监听器、停止前台服务并拒绝新的 MCP 请求。

### FR-02 Root 能力

Android 层必须提供 `unknown`、`available`、`unavailable` 和 `error` 状态以及安全的状态依据。Root 不可用时必须提供用户触发的授权尝试；该操作可以请求已安装的 Root 管理器或重新执行受控检查，但不得暗示应用能够为设备获取 Root。Root 可用后必须隐藏该操作。Android 层还必须提供 Root 保护的 `grantAllPermissions`，只枚举 ARMCP APK 声明的权限，使用有界的 `su`/`pm grant` 尝试，不记录命令输出，并返回每项结果。签名权限、特权权限、特殊访问权限和设备策略仍可能拒绝授予，结果必须说明原因。开启自动权限开关前，界面必须要求明确的风险确认。

### FR-03 工具能力检查

每个工具必须在执行前检查自己的能力要求。检查维度包括 Root 状态、Android API 级别、前后台限制和后端支持。操作不支持时不得静默降级。MCP 操作进程必须报告固定的 `operationPermission: read_only` 基线。任何会改变状态或执行命令的能力，都只有在认证令牌的独立工具允许列表中启用后才可用。

### FR-04 令牌策略和只读基线

令牌支持 `one_time`、`reusable`、`fixed_duration` 和 `unlimited`。每个令牌有独立的工具允许列表。新令牌只默认启用只读工具；启动、输入和 Shell 工具默认关闭，`shell_exec` 必须明确保持关闭。一次性令牌在一次成功认证请求后原子消费；可重复令牌直到删除前保持有效；固定时长令牌在服务端时间点过期；不限时令牌没有时间过期但仍可删除。所有模式都受全局开关约束。删除令牌必须删除完整记录，而不是写入撤销状态。

### FR-05 MCP 传输

APK 在 `POST /mcp` 和经过认证的 `GET /mcp` 提供 Streamable HTTP，要求 `Authorization: Bearer <token>`，保留 JSON-RPC 语义并返回结构化 MCP 错误。必须提供适用 MCP 认证配置要求的受保护资源元数据。系统不使用桥接传输。

原型令牌签发器嵌入 APK，用于本地操作流程。其元数据、访问令牌受众和校验行为必须在 LAN 发布前依据当前 MCP 认证规范检查；当前原型不是完整的 OAuth 授权服务器。

### FR-06 调试页面

`GET /debug/` 由 APK 进程提供同源静态内容。页面显示服务/Root 状态，令牌仅保存在内存中，调用 `tools/list`，按 schema 渲染表单，执行 `tools/call`，显示 JSON 结果/错误，并保留最多 50 条脱敏调用记录。成功的 `view_tree` 和 `view_content` 结果提供客户端可选的元素树和边界模型，显示路径、属性、边界、大小和中心坐标；XML 结果显示 XPath，并提供中心点击操作。页面不得执行 MCP 响应中的任意 JavaScript。

### FR-07 LAN 生命周期

服务只能在操作人员明确启用 MCP 时绑定，必须报告有效的局域网地址，并要求 MCP 请求认证。LAN 明文使用和 Android 本地网络权限行为必须在设置及运行手册中明确说明。

### FR-08 调试布局和自动权限尝试

调试页面将标题栏和桌面面板保持在视口内；各面板可以独立滚动，窄屏使用单列页面滚动。结果内容不得把外层网格撑出视口。`view_tree`/`view_content` 检查器的树和边界区域保持相同渲染高度，保留边界模型宽度，允许长路径横向展开，选中框显示为红色并使子元素优先响应，任一侧选中后都将对应树行滚动到可见位置。可选的自动权限设置默认关闭，启用时显示风险提示，并在应用打开或 MCP 启用时调用已有的有界 Root 权限操作。权限结果显示总结果，只逐项列出失败权限。

### FR-09 运行模式和无障碍权限

ARMCP 持久化 `root` 或 `non_root` 运行模式。非 Root 模式使用 ARMCP 无障碍服务执行支持的 UI 检查、手势和输入，并将 Root 专属操作作为不可用状态返回稳定原因。服务未启用时，权限操作打开 Android 无障碍设置。Root 可以请求安全设置变化，但界面仍需重新检查服务状态。

运行模式选择器位于设置。Root 模式下，运行方式与权限页面显示 Root 权限控件；非 Root 模式下只显示 ARMCP 运行支持。主页汇总 Root、非无障碍应用权限和无障碍服务状态。

### FR-12 导航和语言

Flutter 界面通过底部导航提供主页、运行方式与权限、令牌管理和设置。语言偏好支持 `system`、`en` 和 `zh`。`system` 不覆盖 `MaterialApp.locale`，设备语言受支持时跟随设备，不支持时回退英文。显式语言选择覆盖系统语言，并通过原生平台契约持久化。

### FR-10 TalkBack 适配

两种运行模式都提供 TalkBack 适配开关。开启后只保存偏好并检查 TalkBack 是否安装/启用。Root 模式下，该偏好允许在 UI 读取失败时进行有界的安全设置恢复，但不能立即启动 TalkBack。非 Root 模式开启后打开无障碍设置供用户确认。ARMCP 自身服务的窗口内容和手势能力在 Android 及目标应用允许时保持启用。

### FR-11 按需 TalkBack

TalkBack 适配开关只保存操作人员偏好和 MCP/UI 兼容行为。选择 Root 模式或打开页面都不得启动 TalkBack。Root 只能在有界的 UI 读取恢复流程中启动；非 Root 打开 Android 无障碍设置供用户确认。

当 Root 模式的按需 TalkBack 偏好开启时，失败的 `view_tree`/`view_content` 检查可以先通过 Root 截图确认屏幕有可见内容。确认有内容后，ARMCP 可以临时将 TalkBack 加入启用的无障碍服务，重试同一检查，并在重试后恢复完整的原始服务列表和无障碍开关值。恢复流程不得因为尝试过回退而留下 TalkBack 启用状态。

## 非功能需求

- 一个请求执行一个有界操作并返回一个结果。
- Root 检查和工具执行不得阻塞 Flutter UI 线程。
- 令牌值不得出现在普通日志、崩溃报告或调试结果中。
- 错误包含稳定的机器可读错误码。
- 依赖保持精简，优先使用 Flutter/Dart 和 Android/Kotlin 自带能力。
- 审计日志保存元数据、结果、耗时和错误码，默认不保存令牌材料或敏感载荷。

## 可行性门槛

UI 检查必须披露后端和权限。`view_tree` 直接返回可读取、可解析的 XML，`view_content` 直接返回可读取、可解析的 JSON。带屏幕边界的节点提供左上角坐标、宽度、高度和可用于 `tap` 的整数中心点。主要后端是显式声明 `canRetrieveWindowContent=true` 的 ARMCP 无障碍服务；它选择活动窗口，尽力刷新节点和子节点，在动态窗口失败时有限重试，并在持续更新期间保留最近的完整快照。它不得创建 UiAutomation 会话。只有服务不可用时才允许 Root `uiautomator dump` 回退，并披露注册冲突；服务已连接但窗口暂时不可读时，返回服务错误，不切换回 UiAutomation。ARMCP 不设置层级字节上限。
